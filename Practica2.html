3. Función de Predicción por Producto y Fecha: Comparación Directa con el Valor Real¶

Tal como se requiere en la sustentación, la función predecir_por_producto_y_fecha(product_id, fecha_venta) recibe el ID del producto y la fecha (YYYY-MM-DD), obtiene las variables reales registradas ese día, ejecuta la predicción con el Mejor Modelo SVM (Exp07_SVM_Polinomico_C5) y con el segundo mejor kernel (Exp11_SVM_RBF_Gaussiano_C5), y muestra en pantalla:

  • Valor_Real (u): las unidades realmente vendidas en esa fecha.
  • Prediccion_Mejor_SVM (u): las unidades estimadas por el modelo ganador.
  • Error_Absoluto (u) y Error_Porcentual (%) para verificar la precisión de la predicción.

def predecir_por_producto_y_fecha(product_id, fecha_venta):
    """Predice la demanda de un producto en una fecha específica y la compara con el Valor Real."""
    pid = int(product_id)
    if pid not in catalogo_dict:
        raise ValueError(f"El producto {pid} no existe. IDs válidos: {list(catalogo_dict.keys())}")

    filtro = (df_sales['product_id'] == pid) & (df_sales['fecha_venta'] == str(fecha_venta))
    if not filtro.any():
        fechas_disp = df_sales[df_sales['product_id'] == pid]['fecha_venta']
        raise ValueError(f"Fecha '{fecha_venta}' no encontrada. Rango válido: {fechas_disp.min()} a {fechas_disp.max()}")

    fila = df_sales[filtro].iloc[0]
    X_sample = pd.DataFrame([{
        'stock_en_momento': fila['stock_en_momento'],
        'discount': fila['discount'],
        'temperatura': fila['temperatura'],
        'dia_semana': int(fila['dia_semana']),
        'es_fin_de_semana': int(fila['es_fin_de_semana']),
        'holiday_flag': int(fila['holiday_flag']),
        'product_id': str(pid),
        'categoria': fila['categoria']
    }])

    valor_real = float(fila['cantidad_vendida'])
    pred_poly = float(np.round(modelo_svm_mejor.predict(X_sample)[0], 1))
    pred_rbf = float(np.round(modelo_svm_rbf.predict(X_sample)[0], 1))

    err_abs = float(np.round( abs(valor_real - pred_poly), 1))
    err_pct = float(np.round((err_abs / valor_real) * 100.0, 2)) if valor_real > 0 else 0.0

    return {
        "Producto_ID": pid,
        "Nombre": fila['nombre'],
        "Categoria": fila['categoria'],
        "Fecha": str(fecha_venta),
        "Dia": ["Lun", "Mar", "Mié", "Jue", "Vie", "Sáb", "Dom"][int(fila['dia_semana'])],
        "Descuento": float(fila['discount']),
        "Valor_Real (u)": int(valor_real),
        "Prediccion_SVM_Poly (u)": pred_poly,
        "Prediccion_SVM_RBF (u)": pred_rbf,
        "Error_Abs (u)": err_abs,
        "Error_%": f"{err_pct:.2f}%"
    }

rango_hist = df_sales.groupby('product_id')['cantidad_vendida'].agg(['min', 'max']).to_dict(orient='index')

def predecir_nuevo_sample(product_id, stock_en_momento, discount=1.0, temperatura=18.0,
                          dia_semana=2, holiday_flag=0):
    """Predice la demanda para un nuevo escenario ingresando características personalizadas."""
    pid = int(product_id)
    if pid not in catalogo_dict:
        raise ValueError(f"Producto {pid} no existe en el catálogo: {list(catalogo_dict)}")

    info_prod = catalogo_dict[pid]
    es_finde = 1 if int(dia_semana) >= 5 else 0

    nuevo_df = pd.DataFrame([{
        'stock_en_momento': stock_en_momento, 'discount': discount, 'temperatura': temperatura,
        'dia_semana': dia_semana, 'es_fin_de_semana': es_finde, 'holiday_flag': holiday_flag,
        'product_id': str(pid), 'categoria': info_prod['categoria']
    }])

    pred_poly = float(np.round(modelo_svm_mejor.predict(nuevo_df)[0], 1))
    pred_rbf = float(np.round(modelo_svm_rbf.predict(nuevo_df)[0], 1))
    consenso = float(np.round((pred_poly + pred_rbf) / 2.0, 1))

    r_min, r_max = rango_hist[pid]['min'], rango_hist[pid]['max']
    alerta = "ALERTA: Quiebre de Stock (Reabastecer)" if pred_poly > stock_en_momento else "OK: Stock Suficiente"

    return {
        "Producto_ID": pid, "Nombre": info_prod['nombre'], "Categoria": info_prod['categoria'],
        "Stock_Disponible": stock_en_momento, "Descuento_Ratio": discount,
        "Fin_de_Semana": "Sí" if es_finde else "No", "Feriado": "Sí" if holiday_flag else "No",
        "Pred_SVM_Poly (u)": pred_poly, "Pred_SVM_RBF (u)": pred_rbf,
        "Rango_Historico (u)": f"{r_min}-{r_max}",
        "Dictamen_Inventario": alerta
    }

8.2 Conclusiones¶

  1. Optimización (Fine Tuning) de las 16 Combinaciones (4 Kernels × 4 Valores de $C$): La evaluación cruzada de los 4 tipos de kernel con los 4 valores de regularización $C \in \{0.1, 1.0, 5.0, 10.0\}$ demostró que un valor bajo de penalización ($C = 0.1$) subajusta severamente los kernels no lineales (RMSE entre 1703.52 u y 2151.42 u), mientras que $C = 5.0$ constituye el punto óptimo de generalización para los kernels Polinómico, RBF Gaussiano y Lineal. El modelo Exp07_SVM_Polinomico_C5 ($d=2, C=5.0$) fue el ganador global de las 16 pruebas con un RMSE de 574.37 unidades, un MAE de 303.42 unidades y un $R^2$ de 0.9206, reduciendo el RMSE en un 66.3 % respecto a $C=0.1$ (1703.52 u) y superando a $C=10.0$ (599.74 u), donde empieza un ligero sobreajuste.

  2. Comparación entre Tipos de Kernel: Los kernels no lineales suaves —Polinómico ($C=5$, RMSE = 574.37 u, $R^2 = 0.9206$) y RBF Gaussiano ($C=5$, RMSE = 609.45 u, $R^2 = 0.9106$)— capturaron con alta precisión la interacción multiplicativa entre producto, descuentos y días feriados/fines de semana. En contraste, el Kernel Lineal ($C=5$, RMSE = 953.35 u, $R^2 = 0.7811$) carece de flexibilidad para modelar curvaturas de demanda, y el Kernel Sigmoide ($C=10$, RMSE = 1076.84 u, $R^2 = 0.7207$) obtuvo el menor desempeño debido a que la función $ anh(\gamma \langle x_i, x_j angle + r)$ no es semidefinida positiva (condición de Mercer) en todo el dominio.

  3. Trazabilidad en MLflow (Training Runs, Datasets y Models): El registro estructurado en MLflow permitió almacenar las 16 ejecuciones con sus 16 gráficas individuales de evaluación, las gráficas comparativas generales, los datasets en la pestaña Datasets y los 5 modelos ganadores en el registro oficial de modelos (Models / Model Registry): Mejor_Modelo_SVM_Global y los 4 mejores modelos por tipo de kernel (Mejor_SVM_Polinomico, Mejor_SVM_RBF_Gaussiano, Mejor_SVM_Lineal y Mejor_SVM_Sigmoide).

  4. Validación por Producto y Fecha (Valor Real vs. Valor Predicho) y Explicabilidad: La función predecir_por_producto_y_fecha(product_id, fecha_venta) permitió contrastar directamente las predicciones del modelo contra la demanda real ocurrida en fechas específicas del historial (con errores porcentuales entre 0.04 % y 4.07 % en las consultas evaluadas), además de simular nuevos escenarios mediante predecir_nuevo_sample(). Finalmente, Permutation Feature Importance confirmó que la identidad y categoría del producto (product_id, categoria), seguidas del indicador de feriado (holiday_flag), el descuento comercial (discount) y el efecto fin de semana (es_fin_de_semana), son los factores determinantes de la predicción.
