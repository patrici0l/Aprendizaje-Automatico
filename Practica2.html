5. Función de Predicción para Nuevos Samples (SVM y Random Forest)¶

predecir_nuevo_sample() recibe los datos de un nuevo caso (producto, stock, descuento, temperatura, día y feriado), valida las entradas, predice con el SVM afinado (Exp06_SVM_Polinomico_d2_C5) y con el Random Forest de referencia (Exp17_RandomForest_Base_100), y compara la demanda estimada con el stock disponible. También informa el rango histórico del producto para verificar la coherencia de la predicción. Se evalúa con 4 casos distintos (4 categorías y escenarios diferentes) y con un análisis de sensibilidad al descuento.

catalogo_dict = df_inv.set_index('product_id').to_dict(orient='index')
rango_hist = df_sales.groupby('product_id')['cantidad_vendida'].agg(['min', 'max']).to_dict(orient='index')


def predecir_nuevo_sample(product_id, stock_en_momento, discount=1.0, temperatura=18.0,
                          dia_semana=2, holiday_flag=0):
    """Predice la demanda (unidades) de un nuevo sample con el SVM afinado y el Random Forest.

    Parámetros
    ----------
    product_id : int          ID del producto del catálogo (inventory.csv).
    stock_en_momento : int    Unidades disponibles en percha (>= 0).
    discount : float          Factor de precio (1.0 = sin descuento, 0.80 = 20 % de descuento; rango 0.5-1.0).
    temperatura : float       Temperatura en °C.
    dia_semana : int          0 = lunes ... 6 = domingo.
    holiday_flag : int        1 si es feriado, 0 si no.

    Retorna un diccionario con las predicciones de ambos modelos, su consenso y el dictamen de inventario.
    """
    if int(product_id) not in catalogo_dict:
        raise ValueError(f"Producto {product_id} no existe en el catálogo: {list(catalogo_dict)}")
    if stock_en_momento < 0:
        raise ValueError("El stock no puede ser negativo.")
    if not 0.5 <= discount <= 1.0:
        raise ValueError("discount debe estar entre 0.5 y 1.0 (1.0 = sin descuento).")
    if int(dia_semana) not in range(7):
        raise ValueError("dia_semana debe estar entre 0 (lunes) y 6 (domingo).")
    if int(holiday_flag) not in (0, 1):
        raise ValueError("holiday_flag debe ser 0 o 1.")

    info_prod = catalogo_dict[int(product_id)]
    es_finde = 1 if int(dia_semana) >= 5 else 0

    nuevo_df = pd.DataFrame([{
        'stock_en_momento': stock_en_momento, 'discount': discount, 'temperatura': temperatura,
        'dia_semana': dia_semana, 'es_fin_de_semana': es_finde, 'holiday_flag': holiday_flag,
        'product_id': str(product_id), 'categoria': info_prod['categoria']
    }])

    pred_rf = float(np.round(modelo_rf.predict(nuevo_df)[0], 1))
    pred_svm = float(np.round(modelo_svm.predict(nuevo_df)[0], 1))
    consenso = float(np.round((pred_rf + pred_svm) / 2.0, 1))

    r_min, r_max = rango_hist[int(product_id)]['min'], rango_hist[int(product_id)]['max']
    dentro = all(r_min * 0.5 <= p <= r_max * 1.25 for p in (pred_rf, pred_svm))
    alerta = "ALERTA: Quiebre de Stock (Reabastecer)" if consenso > stock_en_momento else "OK: Stock Suficiente"

    return {
        "Producto_ID": int(product_id), "Nombre": info_prod['nombre'], "Categoria": info_prod['categoria'],
        "Stock_Disponible": stock_en_momento, "Descuento_Ratio": discount,
        "Fin_de_Semana": "Sí" if es_finde else "No", "Feriado": "Sí" if holiday_flag else "No",
        "Prediccion_SVM (u)": pred_svm, "Prediccion_RF (u)": pred_rf, "Consenso_Media (u)": consenso,
        "Rango_Historico (u)": f"{r_min}-{r_max}",
        "Validez": "Dentro de lo histórico" if dentro else "Revisar: fuera del rango histórico",
        "Dictamen_Inventario": alerta
    }

8.2 Conclusiones¶

  1. Efecto del Fine Tuning y Selección del Kernel en SVM: La exploración sistemática de 16 configuraciones de SVM (4 kernels × 4 variantes) más la búsqueda exhaustiva con GridSearchCV (96 combinaciones × 5 folds = 480 ajustes) demostró que el desempeño de SVR depende críticamente del tipo de kernel y de la regularización $C$. Dentro de la familia SVM, el Kernel Polinómico de grado 2 con $C=5.0$ (Exp06_SVM_Polinomico_d2_C5) alcanzó el mejor resultado con un RMSE de 574.37 unidades, un $R^2$ de 0.9206 y el menor MAE de todos los 19 experimentos (303.42 unidades). Aumentar la regularización de $C=1.0$ (Exp05, RMSE = 902.29 u) a $C=5.0$ (Exp06, RMSE = 574.37 u) redujo el error cuadrático medio en un 36.3 %, mientras que pasar a grado 3 (Exp08, RMSE = 671.65 u) o a $C=10.0$ en GridSearchCV (Exp19, RMSE = 599.74 u) incrementó ligeramente la varianza en el conjunto de prueba.

  2. Comparación entre Kernels No Lineales, Lineal y Sigmoide: Los kernels capaces de modelar interacciones no lineales suaves —Polinómico d=2 (RMSE = 574.37 u) y RBF Gaussiano (Exp10, RMSE = 609.45 u, $R^2 = 0.9106$)— superaron por amplio margen al Kernel Lineal (Exp02, RMSE = 961.96 u, $R^2 = 0.7771$), debido a que el efecto conjunto de descuentos, días de fin de semana y escala por producto es multiplicativo. Por su parte, el Kernel Sigmoide presentó el peor rendimiento (RMSE entre 1076.84 u en Exp16 y 1899.57 u en Exp15, con $R^2$ hasta 0.1310), ya que la función $ anh(\gamma \langle x_i, x_j angle + r)$ solo cumple la condición de Mercer (semidefinida positiva) para combinaciones muy restringidas de parámetros.

  3. Desempeño SVM Afinado vs. Random Forest (Precisión y Eficiencia): El modelo de referencia Exp17_RandomForest_Base_100 obtuvo el menor RMSE global (537.39 u, $R^2 = 0.9305$), superando por 36.98 u en RMSE al mejor SVM (Exp06, 574.37 u). Sin embargo, el SVM Polinómico (Exp06) obtuvo un menor error absoluto medio (MAE de 303.42 u vs. 309.93 u en RF) y se entrenó en 26.9 ms, siendo 4.2 veces más rápido que Exp17_RandomForest_Base_100 (112.0 ms) y 11.5 veces más rápido que Exp18_RandomForest_Optimizado_300 (310.0 ms). La transformación logarítmica del objetivo (TransformedTargetRegressor con $\log(1+y)$) fue determinante para estabilizar las predicciones de SVR frente a productos con escalas desde 31 hasta 6272 unidades promedio.

  4. Interpretabilidad y Función de Predicción en Escenarios de Negocio: El análisis de Permutation Feature Importance confirmó que la identificación del producto (product_id) y su categoría (categoria), junto con las variables promocionales y temporales (discount, dia_semana, es_fin_de_semana), son las que más incrementan el RMSE al ser permutadas. La función predecir_nuevo_sample(), validada sobre 4 casos de categorías distintas (Accesorios, Audio, Computación y Telefonía) y 2 escenarios de sensibilidad al descuento, demostró que un descuento del 20 % incrementa sustancialmente la demanda proyectada y permite emitir alertas preventivas de quiebre de stock.
